    categorical features: ['plant_id', 'building_id', 'department_id', 'machine_id', 'machine_type', 'operating_status']

    encoded columns     : 44
  Deviation: residual = actual kWh - expected kWh; abs deviation = |residual|;
    % deviation = 100*residual/expected only where expected >= 1.0 kWh (else blank);
    excess CO2e (kg) = residual kWh x 0.82 kg/kWh.
  Residual z-score: robust (median / 1.4826*MAD) per machine, global fallback if < 30 residuals.
  Isolation Forest features: residual_z, residual_z_roll4, residual_z_roll12, residual_kWh (trailing windows: 4 and 12 records per machine).
  Detection is unsupervised: no labels are used for fitting or thresholds.
  Residual-z rows with z-flag AND Isolation-Forest flag AND residual>0 are anomalies
  Severity (on |residual z|): low >= 2.5, medium >= 3.5, high >= 5.0.

7. LIMITATIONS & HONEST CAVEATS
  * A flag is a STATISTICAL anomaly (energy use unlike the baseline). It is not a confirmed
    environmental incident; confirmation needs engineering review.
  * Localization stops at the available hierarchy (plant/building/department/machine) and time.
    Within a machine, no sub-component information exists, so none is claimed.
  * The data contain only 4 injected fault episodes (164 records); metrics are indicative only.
  * Injected faults raise consumption by a small amount relative to row-level noise of the
    baseline, so per-record recall is far below the 95% project target; detection is much
    stronger at episode / window level (see sections 5 and 6).
  * Blocked out-of-fold baseline trains on blocks that can lie in the future of the scored block;
    use baseline_strategy='chronological_holdout' for a strict no-lookahead check (scores only
    the final 20% of the timeline).
  * Isolation Forest and robust z-scale are fitted on the same period they score (unsupervised).
  * previous_hour_kwh was verified as past-only and kept; its name suggests an hour but it is the
    sum of the previous 4 fifteen-minute intervals.
